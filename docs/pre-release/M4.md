# M4: access policies, S2 and MQTT

Software implemented with pinned ESP-IDF 5.3.1 / PlatformIO espressif32@6.9.0.
M3 was explicitly accepted by the user on 2026-10-24 and tagged locally v0.3.0.
M4 was accepted by the user on 2026-10-26, covering the remaining stability,
S2/access, live MQTT/recovery/discovery and TLS acceptance points. The user
did not provide an exact flashed revision, timings or measurement traces. This
is user-reported acceptance, not an independent agent bench test. Local tag
v0.4.0 marks this closure; no agent flashing or public publishing. No Arduino or external dependency was added.

## Access and S2

The initial default is Full, as requested by the user. An unversioned old View
policy migrates once to Full; a saved None remains None. A NVS defaults marker
prevents this migration from overriding later choices, including View. New
policy writes persist that marker alongside the selected policy. Corrupt policy
or marker values fail closed. Persisted None/View/Full remains in the M3 NVS key. None denies all ordinary
HTTP endpoints and streams; acquisition, LCD and MQTT are independent. View
allows readings, status, bounded raw capture and SSE; Full also allows access
and MQTT configuration. Wi-Fi-only setup remains isolated even under temporary
Full. Invalid policy values fail closed.

`OpenP1 input and display → Enable S2 GPIO35` is **off by default**. Verify the
external/onboard pull-up resistor before enabling: GPIO35 has no internal
pull-up. No hardware resistor validation is claimed. The input is active-low,
polled with a 10 ms worker delay and debounced for at least 50 ms. During
setup, captive DNS receive may add up to 10 ms; other network operations may
also add latency. A 100 ms-tap regression test guards the normal polling case. Booting with S2 held does
nothing until a debounced release.

Short release grants Full for 300 seconds using monotonic time. The LCD
alternates remaining time with the existing network/IP information; readings
remain visible. Expiry restores the persisted policy, including policy changes
made during the grant. Reboot cancels the grant. A persisted Full stays Full.

Holding for eight seconds shows a visible countdown starting after one second,
erases **only** the Wi-Fi key, commits it, then reboots after one second.
The release after a long press never also grants Full. MQTT configuration and
access policy are preserved. Failed NVS writes are logged without secrets;
there is no automatic NVS erase.

## HTTP and live streams

The dashboard shows a settings link during effective Full access. With the
initial Full policy, open `http://<LCD-IP>/settings` directly; no button press
is needed. If a later saved policy is View/None, press enabled S2 first. There is no application
password. Mutations require Full both before body receipt and immediately
before the action, a per-boot CSRF token, canonical station Host and same-origin
Origin when supplied. No CORS is enabled. Writes are limited to one per second.
JSON must be shallow (at most eight levels), NUL-free and within body bounds.

| Endpoint | Minimum policy | Behaviour |
| --- | --- | --- |
| GET `/`, `/api/v1/status`, `/api/v1/values` | View | Existing dashboard/read API, effective access and grant duration |
| GET `/api/v1/raw` | View | Latest four exact raw chunks, sequence/time/source/layer and history overwrite count |
| GET `/api/v1/events` | View | SSE `state` events, one-second worker interval, at most two clients |
| GET `/api/v1/access` | View | Persisted/effective policy and remaining grant seconds |
| GET `/settings`, `/api/v1/session`, `/api/v1/mqtt` | Full | Settings page, CSRF token, sanitized MQTT config/status |
| PUT `/api/v1/access` | Full | `{ "policy": "None" | "View" | "Full" }`, persist after validation |
| PUT `/api/v1/mqtt` | Full | Partial MQTT configuration, persist after validation |
| GET `/api/v1/simulation` | Full | Saved simulation flag/layer/text, anonymized default sequence |
| PUT `/api/v1/simulation` | Full | Validate/persist simulation settings and restart after successful response |

SSE uses asynchronous ESP-IDF requests. Each chunk rechecks current policy;
revocation/expiry to None terminates existing streams, including when the page
was opened during Full. Restoration to View keeps read-only streams authorized.
The worker checks every second and socket writes have the existing three-second
timeout; a blocked send may delay closure by that timeout. Send errors, size
limits and allocation failures close the affected stream. SSE is an additional
read API; the dashboard still uses bounded polling. No WebSocket is claimed.

Raw chunks remain raw, including bad checksums. `layer: wire_hdlc` identifies
input framing, not successful validation. Replay retains its own source/layer.
This endpoint is a bounded tail, not a complete capture export (M5).

## MQTT configuration and use

Use the Full settings page to enter broker hostname/IP, port, optional new
username/password, TLS, optional private PEM CA, topic root, discovery, raw
publication and an NTP server. Broker host is a bare address, without URI,
embedded credentials or path. Defaults: disabled, TLS disabled, port 1883,
public certificate bundle, `pool.ntp.org`, discovery/raw off and an automatic
root `openp1/<12-lowercase-MAC-hex>`. Plain MQTT is the default transport. Enable TLS and select the appropriate
broker port (usually 8883) when certificate-verified encryption is wanted.
Existing saved TLS/port choices are preserved on upgrade.

The settings page hides and disables connection fields while MQTT is off,
and certificate/time fields while TLS is off. Switching visibility preserves
their values. Disabling MQTT submits only the enabled flag; disabling TLS omits
CA/time fields, preserving the saved settings for later use.

Omitted username/password/CA fields preserve stored values; explicit empty
strings clear them. The UI has explicit clear controls and never preloads
secrets. API reads return only configured booleans for username/password/CA.
No MQTT credentials are stored in source, build flags or logs. NVS is ordinary
flash storage; encryption at rest is not claimed. Invalid/corrupt stored config
fails closed; it is not silently erased or connected with reduced security.

TLS always validates the certificate chain and broker hostname. Private CA
PEM must parse successfully; there is no insecure TLS fallback or hostname
bypass. TLS waits for a plausible system time (2024 or later); NTP can be local
for offline networks. Actual chain validity/hostname rejection is performed by
ESP-TLS/Mbed TLS and still needs the live-broker tests below.

- `<root>/<channel>/availability`: retained `online`, retained QoS 1 LWT `offline`.
- `<root>/<channel>/state`: unretained JSON numbers/strings keyed by all OBIS components
  and attribute (`1_0_1_8_1_255_a2`), types, scaler/unit metadata, timestamps and
  per-reading stale status. At most 24576 bytes, every five seconds or after a
  new notification; failed frames do not erase last good readings.
- `<root>/<channel>/raw`: optional, unretained raw hex with sequence, timestamp, source
  and layer. Four-slot queue of at most 256 bytes each; queue/send failures are
  counted in `raw_dropped`. Best effort: acquisition history can also overrun
  before publication; sequence gaps reveal loss. Not a replay/export guarantee.
- `homeassistant/sensor/openp1_<device>/<object-key>/config`: optional retained
  discovery for numeric attribute-2 objects. Stable unique IDs, transmitted
  units, appropriate power/energy/current/voltage/frequency classes and
  total-increasing energy registers. Availability requires both global online
  and a fresh reading. Reconnect republishes discovery. Disabling discovery
  stops advertising but does not remove already retained entities; remove
  old retained configs manually when moving brokers or retiring entities.

The MQTT worker never reads access policy, so None cannot stop publication.
Per user decision on 2026-10-25, enabled MQTT publishes in both modes, using
`normal` for UART and `simulation` for replay as `<channel>` above. Provisioning
and unavailable station connectivity still suppress connections/publications.
Home Assistant simulation discovery uses `openp1_<device>_simulation` rather
than the normal device identity, and its device/entity names include simulation.
Normal discovery identities remain stable, with their state/availability topics
updated to the normal branch. Old direct subscriptions to `<root>/state` must
move to `<root>/normal/state` (and similarly for raw/availability).
MQTT reconnect uses the bundled
client's ten-second retry interval and a thirty-second keepalive. The outbox is
bounded to 8192 bytes (reduced 2026-10-25) and individual discovery to 2048. Graceful reconfiguration
publishes offline to the old broker before replacing its client when possible.

## Ownership and memory limits

Acquisition remains the sole owner of meter parsing and raw input. It submits
fixed snapshots without waiting for sockets, DNS, broker, configuration or TLS.
The raw diagnostic tail adds four fixed 256-byte records. HTTP/SSE/MQTT take
independent bounded heap copies of the existing 64-object/8192-byte value pool;
allocation failure is reported or the stream closed. MQTT worker stack 8 KiB,
MQTT client 6 KiB, SSE worker 4 KiB; HTTP remains 12 KiB with three client sockets.
M4 also limits MQTT host/NTP to 128 bytes, username 64, password 128, root 96,
private CA 3072 and JSON configuration upload 8192. Access bodies are at most
64 bytes; Wi-Fi setup retains its own 384-byte bound. No persistent upload or
filesystem capture storage is added.

real broker or Home Assistant acceptance. See CHANGELOG for builds actually run.

## Debug console allocation crash follow-up (2026-10-25)

The user supplied repeated `abort()`/`SW_CPU_RESET` logs. The local ELF SHA256
`f7fea904da0dbbb9fdac55d44652432189fbc72c4e42595988a144191fb092ec` matches
the device log prefix. `addr2line` resolves the failure through
`__wrap___cxa_allocate_exception` -> throwing `operator new` -> nothrow
`operator new` -> `admin_get` at the former debug History allocation. The
failure is a debug-console allocation failure, not evidence that replay bytes
or the replay pause caused the abort. The earlier host tests/build did not
exercise this device memory pressure.

Remove the approximately 20 KiB per-poll history copy; serialize one entry at a
time and check access before every HTTP chunk. Replace fallible nothrow-new
allocations in HTTP/MQTT with checked C allocation and placement construction.
Regression checks cover 100 full-history reads with allocations >=8192 bytes
rejected, record loss during overwrite/clear, JSON escaping, access expiry
mid-response, JSON allocation failure and unavailable responses on failed
snapshot/config/request-body allocations. The allocation helper is also tested
with C++ exceptions disabled. Native, HTTP/SSE/MQTT and embedded web tests pass,
as does the pinned PlatformIO ESP-IDF simulation build. HTTP/MQTT tests also
pass AddressSanitizer/UBSan; leak detection was disabled because LeakSanitizer
cannot run under this sandbox's tracing. The physical device still needs a sustained test
with the settings console open; no flash or M4 acceptance/tag is claimed.

## Runtime simulation settings follow-up (2026-10-25)

As explicitly requested, simulation is configured through Settings rather than
menuconfig. It defaults off on first setup, persists its flag/format/sequence in
a versioned NVS blob and uses the same shared decoding pipeline. The supplied
default APDU has only its serial/GR identifiers replaced with 12345678/1234567.
The editor is bounded to 4096 text characters / 2048 raw bytes, and distinguishes
HDLC frames from already-reassembled LLC/APDU without wrapping either one.
Save and restart is explicit in the UI. A delayed restart is requested only
after a successful save response; failed validation/commit does not apply a new
configuration. Missing/corrupt simulation settings use UART defaults.

Checks cover anonymous defaults and identical remaining capture bytes/readings,
cycle timing, malformed input and exact raw-byte/layer preservation, initial
disabled state, persisted enabled state, corrupt fallback, failed commits,
restart wrap timing, access/CSRF/expiry/bounds and embedded settings actions.
Pinned ESP-IDF compilation and host ASan/UBSan checks pass. Physical save/reboot
and return-to-UART tests remain pending; no hardware was flashed.

## MQTT text format follow-up (2026-10-25)

Settings now includes text compatibility enable and ID-label controls, using
the same MQTT client and configuration. The additional topics are
`<prefix>/<normal|simulation>/text/{raw,hdlc,id,active,voltage,current,metering}`.
The former JSON `/raw` publisher is removed; text mode enables both
hexadecimal text topics. `hdlc` follows the supplied old name but carries
LLC/APDU bytes, not a frame with a synthesized checksum. ID defaults to the
user-supplied ISK label and can be changed or omitted. No manufacturer inference
is claimed. The old NVS configuration is migrated without losing broker settings.

Diagnostic text is best effort: a four-frame queue (2049 bytes/frame) and one
pending 2048-byte reassembly slot; oversize packets are omitted, never truncated
and published as complete. Allocation/queue/mailbox/send loss is counted by
`text_dropped` in the sanitized MQTT API and displayed in Settings. Resources
are allocated only on first use and kept for the boot lifetime. JSON diagnostics
continue preserving their independent bounded raw chunks and source metadata.

Checks reproduce all four numeric lines of the user's October-25 example.
Observer tests compare all original frames and reassembled bytes, fragmenting
input one byte at a time with embedded flags and CRC-invalid input. Service
tests cover both sources/custom prefixes, original JSON coexistence, text
disabling, raw gating, NVS-v1 migration, oversize omission/counters and TLS/
provisioning/access behavior. Native, embedded web, HTTP/service ASan/UBSan
checks and the pinned ESP-IDF build pass. Live broker/legacy-consumer testing
remains pending; no hardware was flashed or milestone tagged.
The final native run used an isolated working copy with the original tracked
isk-4 fixture; the user's concurrent local append to that fixture was preserved
and excluded from this change.

## Decoder/MQTT allocation-abort follow-up (2026-10-25)

The supplied ELF SHA matches local firmware exactly:
`38f30d39e1aafdd3e2965e9099f99ead454ef3c7611afad8d1aa3caaaab9bdab`.
One backtrace reaches Reader::value vector growth through simulation decoding;
the other reaches MQTT state_json key allocation. Both abort because exceptions
were disabled. The repeated Wi-Fi connecting message does not explain these stacks.

The correction makes debug history lazy, exact-reserves parsed nodes/children,
removes dynamic JSON keys/discovery-cache strings, enables allocation exceptions
with a warmed 2048-byte emergency pool, adds recovery boundaries and caps dynamic
Wi-Fi RX/TX buffers at 10/8. Last committed readings/raw bytes survive decoder
allocation failure. Failed JSON builds are omitted and partial trees freed.
HTTP can return unavailable; MQTT retries. Startup/status heap statistics expose
free bytes, largest block and the minimum-free watermark for physical checks.

Tests sweep 160 refused-allocation positions through repeated decode cycles,
verify unchanged readings/document and subsequent recovery, and check JSON
cleanup under C/C++ allocation failure. Lazy debug, HTTP and MQTT recovery tests,
ASan/UBSan (leak detection disabled under tracing), embedded UI checks and the
pinned ESP-IDF build pass. Generated headers confirm exceptions/pool/buffer caps;
the final ELF contains the real exception allocator rather than the abort stub.
Native regressions used original tracked isk-4 data in an isolated copy, leaving
the user's local capture append intact. No hardware was flashed or tag created.
Physical soak testing with MQTT/raw/text/discovery, dashboard and MQTT status polling
remains pending; inspect heap watermarks and continued reading/publication counts.

## Wi-Fi/MQTT memory starvation follow-up (2026-10-25)

The latest user logs show ENOMEM and failed radio timer allocations while replay
continues. The display full DMA buffer was still reserving 64800 bytes. Replacing
it with a 3840-byte band releases 60960 allocation bytes; reduce the QoS outbox
cap from 32 to 8 KiB and defer MQTT recreation for 15 seconds after allocation
failure. Pixel/rotation/bounds and cooldown/recovery tests cover the changes.
Hardware stability, free heap and display transfer timing still need validation.
