# M5: configuration and read-only diagnostics (revised scope)

M4 and the revised M5 scope were accepted by the user on 2026-10-26. M5 is
complete and tagged locally v0.5.0. Electrical compatibility remains an M7 item.

## Existing foundations

Persisted access, display/gauge, MQTT, and bounded runtime simulation settings
already exist. UART and replay use the shared parser; source MQTT branches are
isolated. Raw bytes, errors, decoded unknown objects and last-good readings are
retained in bounded RAM. These do not yet constitute full diagnostic exchange.

## First delivery: persisted UART settings

Settings → Meter UART exposes baud (300-115200), None/Even/Odd parity, one/two
stop bits and RX inversion. UART1 stays at 8 data bits on GPIO27. Full access,
station origin and CSRF are checked server-side; bodies are capped at 256 bytes.
Unknown/duplicate fields and invalid types/ranges are rejected. Partial updates
preserve other serial fields. NVS commit precedes a success response; only after
that response is sent is the existing 1500 ms restart scheduled.

`config/serial.cpp` stores a versioned fixed 12-byte NVS record, using board
menuconfig values only as defaults when no valid stored settings exist. The
user-requested default is now 115200 8N1 with RX inversion, matching the
reference ESP8266 project; saved UART settings remain unchanged. Boot
settings remain immutable during acquisition. Corrupted NVS falls back to the
board defaults, logs an error, preserves the corrupt record and permits repair
through Settings. Saving does not switch UART/simulation source; return to UART
through the existing Simulation settings. No new task or large buffer is added.

Checks: version/size/enum/baud validation, save/reboot reload, immutable boot
values, failed commit recovery, access/origin/CSRF guards, restart deadline,
UI serialization/restart page, HTTP/MQTT ASan/UBSan and ESP-IDF build pass.
Real UART parameter/return-from-simulation acceptance remains pending for M5.

Remove the previously unimplemented items 1, 2, 3, 4, 5 and 7: diagnostic
export, capture import, replay pause/resume, replay speed, configurable loop
on/off, and capture copy/download controls. These are not deferred M5 blockers.
Existing simulation selection/text editing and its fixed repeat remain intact.
No upload/export/copy/download or advanced replay controls are added.

## Delivery: read-only diagnostics page (item 6)

`/diagnostics` is linked from readings and Settings. View/Full can read it;
None gets the S1 waiting shell. Protected values/raw APIs are checked for each
poll, and setup AP never exposes this page's data. Three panels show raw bytes,
decoded scalar/string values (including unknown OBIS), and counters/latest parser
error. Display sample type, raw numeric value, scaler/unit and timestamps/age.
The page issues values then raw sequentially every three seconds with eight-
second deadlines. A failure clears displayed snapshots and reports unavailable;
403 clears them and navigates to the waiting page. All device values use DOM
textContent, never HTML interpolation. No credentials are read.

Bounds and limitations: show the existing last four 256-byte raw chunks and up
to 64 decoded scalar/string readings. Raw chunks are not claimed as complete
validated frames; the tail can begin mid-frame. Raw/decoded responses are separate
snapshots. Unsupported nested values remain in the processor/raw pipeline but
are not serialized into this page. Only counters/latest parser error exist, not
an error-history ring. No new firmware buffer/task or capture storage is added;
raw JSON serialization now rejects partial allocation failures with 503.
