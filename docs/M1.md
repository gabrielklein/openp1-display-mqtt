# M1: raw input

Historical milestone report: the compile-time replay controls described below
were replaced on 2026-10-25 by **Settings → Simulation → Save simulation and
restart**. See README.md for the current runtime behavior and bounds.


Historical M1 baseline. M2 now adds protocol decoding and a display driver;
see [M2](M2.md) for the current implementation and pending physical check.

M1 implements raw acquisition only. No HDLC frame validation, reassembly,
DLMS decoding, readings, display, network or MQTT publication exists yet.
Invalid checksums, embedded 0x7e flags and incomplete frames remain unchanged
in raw history; protocol validation belongs to M2.

## Firmware configuration

Run `pio run -e tenstar_tdisplay -t menuconfig`, then open **OpenP1 input and display**.
UART1 uses GPIO27 with eight data bits, selectable 300–115200 baud,
None/Even/Odd parity, one/two stop bits and RX inversion. Defaults are
9600 8N1 inverted, still unverified on the meter. UART0 remains for USB debug.
These settings are compiled in; persistent runtime configuration belongs to M5.

Enable replay to disable UART acquisition entirely. Enter hex input or
`topic/with/slash 7ea0007e` and explicitly select wire HDLC or LLC/APDU.
Replay feeds the same capture pipeline in chunks of 1–256 bytes every 20 ms,
then stops. It does not infer validity or add framing/checksums. It is a
simulation with no MQTT implementation/publication. Pause, variable speed,
loop controls and JSONL import remain M5 work.

The portable Replay loader also accepts multiple newline-separated hex/MQTT
records. Blank lines are ignored. Every other malformed or unsupported line
is rejected with its line number, including JSONL; unsupported lines are never
silently discarded. A failed load clears the old replay. MQTT topics must
contain a slash; the caller identifies the layer, since old topic names do
not reliably identify an HDLC envelope. Replay joins bytes in file order;
line breaks are source chunks, not protocol frame boundaries. Original line
timing is not available in these formats.

## Bounds and ownership

- UART driver RX buffer: 4096 bytes; event queue: 32 events.
- Read/capture chunk: at most 256 bytes.
- Raw history: 32 chunks (at most 8192 raw bytes), in acquisition-task ownership.
  Oldest chunks are overwritten; `overwritten()` counts lost history chunks.
- UART overflow/parity/frame/break events increment `uart_errors()`. Queued
  bytes are drained without flushing. Hardware/driver overruns can lose bytes;
  this is not lossless persistent recording. No raw bytes are logged.
- Replay input: at most 65536 text bytes, 4096 per line, 16384 decoded bytes.
  Loading is transactional and memory is bounded; callers must enforce the
  text limit before accumulating an external upload. There is no upload endpoint.
- Hex parsing has a default 16384-byte output limit and supports a smaller
  caller limit; failures leave the caller's previous output unchanged.

`Pipeline::at()` is for the owning task only, with index less than `size()`.
Future HTTP/display consumers must implement synchronized snapshots. No flash
filesystem is mounted: bounded RAM suffices for M1; persistent capture storage
and upload limits will be addressed in M5.

## Checks

`sh scripts/test-native.sh` checks hex parsing, serial setting validation,
replay byte fidelity across chunk sizes, malformed and oversized input,
source exclusion, explicit APDU layering and ring overwrite counters.
Synthetic truncated/checksum-invalid bytes are preserved, not validated.
M2 must add complete real captures and protocol error/segmentation tests.

Verified builds: default 9600 8N1 inverted UART, non-inverted 8E2 UART,
and LLC/APDU replay with one-byte chunks, using espressif32@6.9.0 and
ESP-IDF 5.3.1. The final local build uses the default UART configuration.
Physical UART polarity/baud/overflow behaviour, board and meter electrical
compatibility are unverified. No hardware has been flashed or bench tested.
