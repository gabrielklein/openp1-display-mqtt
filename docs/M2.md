# M2: HDLC, DLMS/OBIS and display

M2 accepted on 2026-10-23 following user-run physical display and replay tests.
The user confirms readable, correctly oriented and unclipped text, then confirms
the requested replay checks (measurements, pagination, SIMULATION and stale state).
Exact flashed revision was not supplied. No flashing was performed by the agent.

## Protocol path

Both UART and replay first retain the untouched source chunk in the M1 raw
ring, then synchronously feed the same portable processor. Processing does
not wait for the display. Switching source resets protocol/reading state so
simulation cannot inherit live meter readings. Raw history keeps source labels.
UART overflow/parity/frame/break errors discard partial decoding and record
an error without erasing last good readings.

The HDLC parser reads format type A and the 11-bit declared length (7–2047
body bytes), then requires the closing flag at exactly that position. It does
not split on flags inside data. Variable-length addresses (1/2/4 octets), HCS
when information is present and FCS are checked. CRC is CRC-16/X-25 with
low-byte-first transmission. Empty link frames have FCS only. Shared/idle
flags are accepted. Legal supervisory frames between segments are ignored;
a link-management frame interrupts pending reassembly with an error.

Reassembly is limited to 8192 information bytes, the same source/destination
and control family, and two seconds of inactivity (including partial frames).
Segmented I frames require contiguous N(S), modulo 8. The supplied meter
uses segmented UI frames 03/13, which carry no N(S): no sequence number is
invented. Each segment still passes HCS/FCS and the assembled notification
must decode completely. Lost/reordered samples in tests are rejected. UI
provides no way to prove the order of all possible individually valid segment
substitutions; it is not an authenticated transport. Corrupt lengths are
recovered conservatively by declared boundaries, timeout or explicit end of
input, not by interpreting arbitrary embedded flags as new frames.

Validated wire packets must begin with inbound LLC E6 E7 00. Explicit
LLC/APDU replay may omit LLC; it is bounded until end of replay, never marked
HDLC-validated, and supports one notification per input. HDLC replay supports
multiple notifications. Replay end detects truncated frames/segments and
commits a complete direct APDU. Unsupported LLC/APDU, including encrypted
notifications, is reported and leaves last good readings unchanged.

## A-XDR and objects

Data-notification APDU 0F: preserve invoke ID and the optional raw 12-byte
meter timestamp. Decode null, arrays/structures, boolean, bit strings, signed
and unsigned integers through 64 bits, enums, float32/64, octet/visible/UTF-8
strings, BCD bytes and fixed date/time values. Date/time/string/BCD contents
are retained without semantic conversion. Compact arrays and unknown wire
types fail explicitly because their size cannot safely be guessed.

The complete bounded flat tree retains type tags and offsets into the exact
APDU bytes, including unmapped structures and unknown OBIS objects. Map the
supplied self-describing {OBIS, value[, scaler-unit]} entries; also accept an
explicit descriptor/value list and the push-list-self-descriptor form (class
40 attribute 2), with class/attribute/data-index association checked. Register
classes 3/4 may obtain scaler/unit from an explicit matching attribute 3.
Other layouts remain inspectable trees, without guessed field positions.
No scaler or unit is inferred from an OBIS name. Unknown units keep their
numeric enum. Missing scaler/unit is labelled RAW. Partial attribute selection
is retained in the tree, not represented as a whole register value.

Reading updates are transactional: malformed/ambiguous mapping, duplicate
identifiers, nonfinite numbers and limits cannot overwrite good values.
Null/unavailable values stay in the document without erasing an existing
numeric sample. Omitted readings retain their own last-success timestamp.
Each retained sample owns its exact A-XDR value bytes, numeric type, raw
number, scaler, unit and OBIS. Display calculations use doubles; integers
above 2^53 remain exact in encoded bytes, although their double projection
can lose precision. Energy stays in transmitted Wh; no invented missing zeros.

## Bounds and ownership

- Main acquisition task stack: 8192 bytes to accommodate bounded recursive A-XDR parsing.
- HDLC body: 2047 bytes; reassembled or direct LLC/APDU: 8192 bytes.
- A-XDR tree: 256 nodes, depth 12 (root depth 0), 128 children per container;
  string/octet payload at most 1024 bytes, bit string at most 8192 bits.
- Snapshot: 64 objects and at most 8192 total encoded value bytes.
- Last successful parsed document, last error/time and cumulative error,
  notification and validated packet counters. An unvalidated direct replay
  never increments the validated packet counter.
- M1 raw history remains bounded at 32 x 256 bytes with explicit overwrite
  count. It can evict old input even when protocol state retains a reading.
- Single acquisition-task owner of processor and snapshots. Processor/Pipeline
  are noncopyable because framing callbacks reference their owner. Future
  consumers must obtain safe copies, not share mutable tree references.

## Display

The proposed T-Display ST7789 profile uses ESP-IDF's bundled `esp_lcd`, SPI2
at 20 MHz, board pins from HARDWARE.md, 240x135 landscape, swap XY, mirror X,
gap 40/53 and inversion. No Arduino or external dependency was added.
`OpenP1 input and display` in menuconfig can disable the display for headless
operation. The panel profile is not bench validated on the Tenstar board.

A separate task owns the panel and its 3840-byte DMA band buffer (updated 2026-10-25). A one-item
latest-view queue copies fixed 168-byte views from acquisition without waiting;
intermediate UI updates are intentionally coalesced. DMA completion is awaited
before reusing the buffer. Initialization/allocation failures are logged and
leave acquisition running. The display uses original 5x7 glyphs scaled 2x.

Show source (SIMULATION in replay), last-value age and error count; paginate
three numeric readings every five seconds, with label/unit and value on
separate rows. Every sample becomes visibly stale after 15 seconds (`*`),
without zeroing its value. No readings produces NO READINGS. Unknown unit
enums show U<number>. Age and error count saturate at 9999 on this small UI;
internal timestamps/counters are not truncated. No Wi-Fi/IP exists until M3.

## Verification and remaining acceptance

`sh scripts/test-native.sh` checks M1 plus the four real three-frame user
captures, their exact reassembly against the independent LLC fixture, all
single transport splits and multiple chunk sizes, scalers/units and tariffs,
malformed lengths/addresses, HCS/FCS, truncation, missing/reordered UI segments,
I sequence wrap/rejection, timeouts, shared flags, explicit APDU layering,
unknown objects/units/types, bounded A-XDR, push descriptors, source changes,
retained good values, raw fidelity, rendering bounds and 1000 deterministic
malformed-input trials. The host raster preview was visually inspected;
it does not validate a physical screen. See test/fixtures/README.md for provenance.

PlatformIO checks use pinned espressif32@6.9.0 / ESP-IDF 5.3.1: UART
with display, three-frame HDLC replay with display, and direct LLC/APDU replay
with display disabled. Host configuration checks feed the actual generated
replay string through the shared processor. AddressSanitizer and
UndefinedBehaviorSanitizer run on the protocol suite; leak detection is disabled
because the execution environment traces processes and LeakSanitizer cannot
operate under it. No physical execution is claimed.

For current firmware replay, open **Settings → Simulation**, enable it and
select the input layer. Paste the original raw HDLC payloads including their
flags/checksums, or choose LLC/APDU for an already-reassembled payload. Save
and restart applies the source. The bounded editor accepts actual newline-
separated hex/raw MQTT records; decoded summaries and JSONL are rejected.
No filesystem reader or file-upload endpoint exists yet.

Physical acceptance procedure (subsequently reported successful by the user): board powered from USB with the complete
meter cable disconnected, confirm rotation, offsets, inversion, text, paging,
SIMULATION label and stale/error status using a replay build; record the board,
firmware and observed result in HARDWARE.md/CHANGELOG.md. This work does not
authorize flashing. Electrical meter/board checks from HARDWARE.md remain
unverified. User-reported physical acceptance above permits progression to M3.

## Protocol and panel references

Implementation is original MIT project code; no Gurux/TFT_eSPI code or font
was incorporated. Protocol behaviour was cross-checked against
[Gurux HDLC/notification implementation](https://github.com/Gurux/Gurux.DLMS.cpp/blob/master/development/src/GXDLMS.cpp)
and [push object-list/scaler notes](https://www.gurux.fi/Gurux.DLMS.Push).
The proposed panel pinout and landscape offset were checked against
[LILYGO board profile](https://github.com/Xinyuan-LilyGO/TTGO-T-Display/blob/master/TFT_eSPI/User_Setups/Setup25_TTGO_T_Display.h)
and [rotation profile](https://github.com/Xinyuan-LilyGO/TTGO-T-Display/blob/master/TFT_eSPI/TFT_Drivers/ST7789_Rotation.h).

The later radio-load memory fix replaces full-frame DMA with eight-row transfers.
Both orientations match the full host reference pixel-for-pixel; physical band
refresh/rotation acceptance and a Wi-Fi/MQTT soak test remain pending. No flash
was performed for this change.

## Later LCD overview redesign (2026-10-26)

The original paginated monochrome view above is historical. The current display
uses RGB565 colors, a large fixed import/export power card, small L1/L2/L3
voltages, Wi-Fi strength arcs, MQ connection state and a decoded-message RX
pulse. Network/IP/S1 stay in the footer. The DMA buffer remains 3840 bytes;
rotation applies globally. Host band/full equality and guards include this layout.
Physical color/legibility/refresh acceptance for the redesign is pending.
